# M Hardware & Sanitary — Full-Stack Store

A database-driven product catalog + admin dashboard for a hardware and
sanitary shop. Built with **Flask + SQLAlchemy** on the backend and plain
**HTML / CSS / JavaScript** on the frontend.

---

## 1. Technologies

| Layer     | Tech                                     |
|-----------|------------------------------------------|
| Frontend  | HTML5, CSS3, Vanilla JavaScript          |
| Backend   | Python 3.10+, Flask 3, Flask-SQLAlchemy  |
| Database  | SQLite (default) or PostgreSQL           |
| Extras    | Flask-CORS, python-dotenv, Werkzeug      |

---

## 2. Setup on Windows

```bat
:: 1. Enter the backend folder
cd M-HARDWARE-WEBSITE\backend

:: 2. Create a virtual environment
python -m venv venv

:: 3. Activate it
venv\Scripts\activate

:: 4. Install dependencies
pip install -r requirements.txt

:: 5. Create the database + demo data
python database\seed.py

:: 6. Start the server
python app.py
```

Open your browser:

* **Website** → http://127.0.0.1:5000/
* **Admin**   → http://127.0.0.1:5000/admin/

Default admin login: `admin` / `admin123` — **change this immediately.**

---

## 3. Setup on macOS / Linux

```bash
cd M-HARDWARE-WEBSITE/backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python database/seed.py
python app.py
```

---

## 4. Using PostgreSQL instead of SQLite

1. Install PostgreSQL and create a database:
   ```sql
   CREATE DATABASE mhardware;
   ```
2. Open `backend/.env` and set:
   ```
   DATABASE_URL=postgresql://postgres:yourpassword@localhost:5432/mhardware
   ```
3. Re-run `python database/seed.py`.

## 7. AI assistant

The floating 🤖 button uses a **rule-based assistant** that searches your
real database. It never invents prices, stock or specifications.

To plug in a real LLM later, edit `backend/services/ai_service.py` and set
`AI_API_KEY` in `.env`.

## 9. Troubleshooting

| Problem | Fix |
|---------|-----|
| `ModuleNotFoundError: flask` | Activate the venv and re-run `pip install -r requirements.txt` |
| Port 5000 already in use | Edit `app.py` → `app.run(port=5001)` |
| Images not showing | Make sure `backend/uploads/` exists and you uploaded via the admin |
| Can't log in | Re-run `python database/seed.py` to recreate the admin user |
| Products don't appear | Check the product's category and that it isn't marked out of stock |

## Demo data & database
`backend/mhardware.db` is regenerated by `python database/seed.py` (idempotent), so it need not be committed.
Demo images are offline SVGs from `python database/gen_images.py`.
Copy `backend/.env.example` to `backend/.env` and fill in values.

## AI Product Image Agent

Finds products with a missing/broken image and fills them in. Valid images are never touched.

**Order per product:** valid existing image (kept) -> reference image (processed locally) -> configured AI provider(s) -> SVG fallback (`image_status = fallback`).
Only `image`, `image_status`, `image_provider`, `image_error`, `image_updated_at` are ever changed.
Statuses: `missing`, `processing`, `ready`, `fallback`, `failed`.

**Code:** `services/image_service.py` (orchestrator), `image_generation.py` (provider adapters), `prompt_builder.py`,
`image_processor.py` (1200x1200 WebP + JPG), `image_validator.py`, `svg_fallback.py`, `routes/image_agent.py`, `scripts/generate_images.py`.

### Configuration (`backend/.env`, never committed)
```
IMAGE_PROVIDER=gemini            # empty = no AI calls at all
IMAGE_MODEL=                     # optional model override for the primary provider
IMAGE_FALLBACK_PROVIDERS=        # e.g. openai  (only what you list is ever called)
GEMINI_API_KEY=   OPENAI_API_KEY=   STABILITY_API_KEY=   REPLICATE_API_TOKEN=
REFERENCE_DIR=uploads/references
AUTO_GENERATE_PRODUCT_IMAGES=false
```
A provider is used only if it is listed **and** has a key. Provider APIs and model names change; check the
provider's current docs. Gemini (`/v1beta/interactions`) and OpenAI (`/v1/images/generations|edits`) were checked
against the official docs; the Stability and Replicate adapters are written from their public APIs and are **unverified**.

### Reference images
Put a real photo in `backend/uploads/references/` named `<slug>.jpg|png|webp` (also matched by SKU or product id).
It is used as-is (centred on a clean background, `rembg` used if installed) with no API call.

### CLI (from `backend`)
```
python scripts\generate_images.py --dry-run          # plan + prompts, no API calls
python scripts\generate_images.py --limit 2
python scripts\generate_images.py                    # missing/fallback/failed only
python scripts\generate_images.py --id 42 --regenerate
python scripts\generate_images.py --category tiles --provider gemini
python scripts\generate_images.py --all              # regenerate everything (costs credits)
```

### Admin
Products page: image status column, **Generate Missing Images** (background job with progress + cancel), per-product
image button. Product form: **Generate with AI** next to the manual upload. Dashboard: image counts.
A manual upload always overrides a generated image. Jobs are in memory and are lost on server restart.

### Tests
`python -m unittest tests.test_image_agent -v` (temporary DB and folder, no real API calls).

### Troubleshooting / limits
- "no provider configured": set `IMAGE_PROVIDER` and the matching key in `.env`.
- Images are stored in `backend/uploads/products/`. Many hosts have ephemeral disks, so use persistent storage
  (or move `save_image()` in `image_processor.py` to object storage) before deploying.
- The generated picture is a catalog representation, not proof of the exact physical item.
- Schema upgrade is automatic and non-destructive (`database/migrate.py`, takes a dated `.db.bak-*` copy first).
